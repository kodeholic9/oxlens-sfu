### 1-1. 구조

<a id="DOC.fact.LabelForms"></a>
#### 1-1-1. 라벨 — 꼴과 포함 관계
장 · 절 번호는 생성기가 매긴다 — 원천의 주소는 라벨이다. 점은 이름 공간 주소다: 앞 마디가 뒤 마디를 담는 묶음이다. 영역(장) 아래에 구조(무엇을 주고받나)와 동작(받으면 무엇을 하나)이 있고, 동작은 쪽 → 상태 → 사건으로 좁힌다. 진술은 구조 · 동작을 담지 않고 가리킨다(진술 아래 `→ 구조` 줄).

| 라벨 | 꼴 | 무엇을 가리키나 | 보기 |
|---|---|---|---|
| 진술 | `종류-영역-주제[-세부]` | 산문 진술 하나 — 규칙 · 성질 · 가정 …(종류는 아래 진술 종류 표) | `RULE-SES-CONN-TBIND` · `PROP-ROOM-CONVERGE` |
| 구조 | `영역.갈래.이름` | 주고받는 것의 정의 하나 — 그 장 구조 절의 소절(갈래는 아래 구조 갈래 표) | `SES.op.BIND` · `TRK.type.TrackEntry` |
| 동작 — 클라 | `영역.C.상태.사건` | 클라 상태기의 칸 하나 — 그 상태에서 그 사건이 오면 할 일 | `AFF.C.PUB.switch_in` |
| 동작 — 서버 | `영역.S.사건` | 서버 판단 하나 — 서버는 상태를 라벨에 두지 않고 조건으로 가른다 | `SES.S.bind_new` |
| 동작 — 발언권 서버 | `FLR.S.G.상태.사건` · `FLR.S.P.상태.사건` · `FLR.S.묶음.사건` | 3GPP TS 24.380 의 서버 상태기 둘(G · P) · 상태기 밖 판단 묶음(`gate` · `perm` · `ws` · `away` · `T9`) | `FLR.S.G.TAKEN.enter` · `FLR.S.P.PERMITTED.a_REVOKE` |
| 앞 마디만 | 위 꼴의 앞부분 | 그 아래 전부 — 장 · 쪽 · 상태 단위로 가리킬 때 | `SES.C` = 세션 클라 동작 전부 · `AFF.C.PUB` = `PUB` 상태의 동작 전부 |

| `event` · `backing` | 바깥 사건(효과가 닿는 곳) · 가정-보증 대장 | 바깥 사건 장 |
| `areas` · `kinds` | 영역 약어 · 진술 종류(개념 지도 · 진술 종류에서 짓는다) | 문서 장 |

#### 1-1-3. 동작 마디

| 마디 | 뜻 | 보기 |
|---|---|---|
| `C` · `S` | 쪽 — 클라 · 서버 | `ROOM.C.…` · `ROOM.S.…` |
| 상태(대문자) | 그 영역 클라 상태기의 값 — 값의 뜻은 그 장 상태 소절(`영역.state`)의 값 — 뜻 표 | `JOINED` · `PUB` · `NOPUB` |
| `any` | 어느 상태에서나 같은 경우 | `ROOM.C.any.snapshot_stale` |
| `G` · `P` | 발언권 서버만 — 전체 상태기(general) · 참가자마다 상태기(per-participant) | `FLR.S.G.…` · `FLR.S.P.…` |
| 사건 `rx_<메시지>` | 그 메시지를 받음 — 대문자는 발언권 메시지 이름 | `FLR.C.PREQ.rx_GRANTED` |
| 사건 `a_<메시지>` | 발언권 서버 — 전체 상태기(판정)가 참가자 상태기에 넘긴 사건(원문의 a. 사건) | `FLR.S.P.PERMITTED.a_REVOKE` |
| 사건 `T<번호>` | 그 타이머가 만료됨 | `FLR.C.PREQ.T101` |
| 사건 `enter` | 그 상태에 들어설 때 하는 일 | `FLR.S.G.TAKEN.enter` |
| 꼬리 `_exhaust` | 재전송 횟수 소진 — 마지막 만료 | `FLR.C.PREQ.T101_exhaust` |
| 꼬리 `_ok` · `_fail` | 결과 성공 · 실패 | `LINK.C.REOPEN.reopen_ok` |
| 꼬리 `_stale` | 지금 것이 아닌 것을 받음 — 지난 세대 · 기다리지 않던 응답(무시) | `LINK.C.any.link_event_stale` |
| 꼬리 `_other` | 같은 사건의 나머지 경우 — 따로 이름 붙인 경우에 들지 않는 것 | `FLR.C.PREQ.rx_other` |
| 꼬리 `_discard` | 받고 버린다 | `FLR.S.G.any.req_discard` |

### 1-2. 주제

#### 1-2-1. 범위·용어

<a id="RULE-DOC-SCOPE"></a>**RULE-DOC-SCOPE** · 규칙 — 범위·용어

이 문서는 **클라가 쓰는 핵심 계약**만 정한다.

|              | 이 문서                                                              | 왜                                           |
| ------------ | ----------------------------------------------------------------- | ------------------------------------------- |
| **핵심(core)** | ★**안이다** — 접속·방·미디어 협상·소속·문자·진단·통지·발언권                            | 이것이 없으면 **아무것도 안 된다**                       |
| **확장**       | ★**밖이다** — 주석(`ANNOTATE`)·★**발성 감지**(`svc=0x02`) 등 | 있으면 좋은 것이지 **붙는 조건이 아니다.** 제품마다 다르고 따로 늘어난다 |
| **서버끼리**     | 밖이다 — 게이트웨이↔미디어 서버                                                | 클라가 보지 않는다                                  |
| **운영**       | 밖이다 — `/admin/*` · `/healthz/*`                                   | 운영자 도구다. 클라가 쓰지 않는다                         |

<a id="RULE-DOC-EXT-EXISTS"></a>**RULE-DOC-EXT-EXISTS** · 규칙

★**확장이 밖이라고 없는 것이 아니다.** 서버에는 있고, 쓰려면 **따로 규격을 본다.**
★이 문서의 *"전량 20"*(각 장의 구조)은 ★**핵심의 전량**이지 서버 op 의 전량이 아니다.

<a id="RULE-DOC-TERMS-BASIC"></a>**RULE-DOC-TERMS-BASIC** · 규칙

| 말 | 뜻 |
|---|---|
| **클라** | 브라우저·앱에서 도는 우리 SDK |
| **게이트웨이** | 클라의 WS 를 받는 서버(hub) |
| **미디어 서버** | 실제 미디어를 다루는 서버(sfu). 방마다 하나가 정해진다 |
| **Peer** | 미디어 서버가 사람 × 미디어 서버마다 드는 상태 하나 — 그 사람의 연결 · 방 멤버십 · 발행이 여기 달린다. 서버마다 하나이고 수명은 세션 수명이다(§9-1-1). 그것을 무엇으로 드는가는 서버 정의서 몫이다 |
| **방** | 사람이 모이는 단위 |
| **발언권** | 무전에서 지금 누가 말할 수 있는가 |
| **발행 연결 / 구독 연결** | 클라가 서버와 맺는 WebRTC 연결. ★**`1pc` 면 하나가 둘을 겸하고**(지향점), `2pc` 면 둘로 나뉜다(호환 기준선) — §9-4-5 |
| **트랙** | 미디어 하나(카메라 · 마이크 · 화면) — ★**논리 단위 · 방향 없음.** `track_id` 로 식별한다. 개인 트랙(`individual` — 발행자의 것) · 슬롯 트랙(`slot` — 주인이 방). 방 전원이 같은 값으로 보는 목록 항목이 `TrackEntry` 다(§6-1-1) |

<a id="RULE-DOC-TERMS"></a>**RULE-DOC-TERMS** · 규칙

★**용어는 업계 표준어를 쓴다.** 구현자가 코드에서 부르는 이름과 같아야 한다.

| **지터**                | 백오프에 더하는 무작위 값                                                          | 흔들기     |

| ★**출처 전환**           | ★**다운링크 스트림 밑의 업링크 스트림이 바뀌는 것** — 레이어 전환(시뮬캐스트) · 화자 전환(무전) · 재배정(전이중) 셋. 서버가 seq · timestamp 를 이어 쓴다(§9-4-2) | 갈아 끼우기 |

| ★**ingress / egress**   | ★**서버 기준 들어옴 / 나감** — 업링크 스트림을 받는 쪽 처리 / 다운링크 스트림을 내는 쪽 처리 | 서버 송신 · 서버 수신 |
| ★**트랙 목록**            | 방의 트랙들 — `TrackEntry` 가 나르고(§6-1-1) 방 전원이 같은 값을 본다. 구독 m-line 배정은 구독의 것(★배정표 — 연결마다 하나, §8-1-2) · 발행 정보(`codec`·`ssrc`·`duplex`)는 발행의 것이다 | 스트림(목록 항목을 부를 때) |
| **시뮬캐스트**            | 한 트랙을 업링크 스트림 여럿(`rid` 마다 — 공간 레이어 하나씩)으로 보내는 것                                                   | 화질 여러 단 |
| ★**`rid`**              | ★**업링크 스트림 이름**(`"h"`/`"l"`). SDP 어휘다(§9-4-10)                              | 레이어     |
| ★**spatial / temporal** | ★**구독이 지목하는 레이어 인덱스**(§7-1-2). 정수이고 `0` 이 최저                          | 단    |
| **데이터 채널**            | `RTCDataChannel`. 발언권이 이 위로 간다                                          | 통로      |
| **조립한다**              | 서버 쪽 SDP 를 클라가 만들어 브라우저에 먹인다(§9-4-4)                                        | 짓는다     |
| **축출**                | 같은 신원이 다시 들어와 옛 것을 밀어내는 것                                               | 밀어내기    |
| **소속**(`Affiliation`) | ★**어느 방을 구독하고 어디로 발행하는가** — **방** 단위(§5-1-1)                              | scope   |
| ★**`pub`**            | 발행. **방** 입도 = `pub_room`(§5-1-1) · **트랙** 입도 = `PUBLISH_TRACKS`(§7-1-2) | talk    |
| ★**`sub`**            | 구독. 같은 두 입도 — `sub_rooms` · `SUBSCRIBE_LAYER`                         | listen  |
| ★**통지 권위**           | ★**클라 상태의 출처.** 발언권은 **DC 단일**(§10)                                    | 권위      |
| ★**강제 권위**           | ★**미디어가 실제로 나가는 조건.** 발언권은 publisher prefan 게이트                      | 권위      |
| ★**`duplex`**           | ★**화자의 출처를 정하는 축** — ★**발행 속성**이다(`PUBLISH_TRACKS`·`TRACK_SET`, §7-1-2). ★**구독자에게는 오지 않는다** — 구독자가 보는 것은 트랙 `type`(`individual`/`slot`)과 `active` 뿐(§6-1-1) | 회의방/무전방(방 양식) |

<a id="RULE-DOC-PUB-SUB-GRAIN"></a>**RULE-DOC-PUB-SUB-GRAIN** · 규칙

★★**`pub`/`sub` 를 방과 트랙 두 입도에 같이 쓴다.** 다른 개념이 아니라 ★**같은 축의 입도 차이**다 —
*"어느 방으로 보내나"* 와 *"어떤 트랙을 보내나"* 는 같은 방향의 **굵기만 다른 물음**이고,
같은 낱말을 쓰는 것이 그 정합을 드러낸다. 갈릴 자리는 ★**이름에 입도를 넣어 가른다** —
방은 `sub_rooms`·`pub_room`, 트랙은 `PUBLISH_TRACKS`·`SUBSCRIBE_LAYER`.

<a id="RULE-DOC-AUTHORITY-TWO"></a>**RULE-DOC-AUTHORITY-TWO** · 규칙

★★**"권위" 를 홑으로 쓰지 않는다.** 두 뜻이라 반드시 앞을 붙여 가른다 — ★**통지 권위**는
*"클라가 무엇을 믿는가"*, ★**강제 권위**는 *"무엇이 실제로 막고 흘리는가"* 다. 발언권은 둘이 갈린다:
통지는 DC 가 주고, 실제로 소리를 내보내는 것은 서버의 prefan 게이트다. ★**§1-2-1 이 "같은 것을 다른 말로
부르지 않는다" 고 했으므로 그 반대 — 다른 것을 같은 말로 부르는 것 — 도 막는다.**

<a id="RULE-DOC-IS-CONTRACT"></a>**RULE-DOC-IS-CONTRACT** · 규칙

> ## ★★이 문서는 **계약서**다
>
> ★**미디어 서버(SFU)와 클라 SDK 를 이 문서로 만든다.** 구현을 문서화한 것이 아니다.
>
> | | 무엇인가 |
> |---|---|
> | ★**이 문서** | ★**계약.** 여기 적힌 것이 참이다 |
> | 소스 — `oxlens/oxlens-sfu` · `oxlens-sdk-web` | ★**이 계약의 산물.** 권위가 아니다 |
> | 3GPP TS 24.380 | ★**발언권(§10)의 정본.** 준수한다(§10-4-26) |
>
> ★★**어긋나면 이 문서가 이긴다.** 소스가 다르게 돌면 ★**소스를 고친다** — 단 갈림은 어느 한쪽의 결함이므로 ★**어느 쪽이 결함인지는 결재로 가른다**(규격이 틀렸을 수도 있다). 소스를 근거로 이 문서를 조용히 되돌리지 않는다.
>
> ★**소스는 언제 보나 — 이 문서가 모호할 때만 본다.** *"소스가 이러니까 이렇게 하자"* 가 아니라 ★*"이 자리를 정한 적이 없는데, 소스는 무엇을 하고 있나"* 를 볼 때다. ★**답을 소스에서 가져오되 근거는 여기서 새로 세운다.**
>
> ★**증상** — 소스를 권위로 두면 → ★**결함이 계약이 된다.** 옛 구현이 표준과 어긋난 자리(§10-4-30 subtype · §10-4-31 TLV ID)가 정확히 그렇게 굳었던 자리다.
>
> ---
>
> ★**이 문서만 보고 만들 수 있어야 한다.** 소스를 안 봐도 되게 쓴다.
> ★**언어와 도구가 바뀌어도 다시 구현할 수 있게 쓴다** — 소스를 상대로 이기듯 시간을 상대로도
> 이긴다는 선언이다. 그래서 ★**성립 조건 색인**(아래)이 앞머리에 있다: 재구현 전에 그 전제들이
> 아직 참인지 먼저 확인한다.
> ★**왜 그렇게 정했나**는 각 항의 근거 문장과 ★**증상** 칸에 있다.
> 개정 근거의 상세는 ★**커밋 이력**에 남긴다.
>
> ★**기각 진술(`REJ-…`)이 기각 근거의 자리다** — 본문이 *"하지 않는다"* 고 정한 것의 이유를 든다. 이행 항목(규격은 정했으나 소스가 아직 따라오지 않은 것)은 이 문서에 두지 않는다 — 이 문서는 하위 문서를 가리키지 않는다.

<a id="RULE-DOC-LAYOUT"></a>**RULE-DOC-LAYOUT** · 규칙 — 이 문서의 짜임

**장은 영역, 절은 갈래, 소절은 라벨이다.** 장 · 절 번호는 생성기가 매긴다 — 원천의 주소는 라벨이다(꼴과 낱말은 이 장 구조 절).

| 단 | 무엇 | 본뜬 곳 |
|---|---|---|
| **장** | 영역 하나 — 머리에 그 영역의 정체성 · 수명 · 상태 표와 의존 표. 장 차례는 이 장 구조 절의 영역 표 | — |
| **절 · 구조** | 주고받는 것의 정의 — WS 메시지 · 형 · HTTP · 프레임 · 사실 표 · 상태 칸 · 시한 | 3GPP `Coding` · OpenAPI `components.schemas` · `paths` · 3GPP `Configurable parameters` |

<a id="RULE-DOC-COND-INDEX"></a>**RULE-DOC-COND-INDEX** · 규칙 — ★성립 조건 색인 — 이 문서의 유효기간

본문 곳곳의 ★**성립 조건**을 한 곳에 모은다. ★**하나라도 깨지면 걸린 조항이 조용히 틀린
문서가 된다** — 재구현·개정 전에 이 표부터 본다.

| 전제 | 걸린 조항 |
|---|---|
| `T-bind` 10초 + 백오프 표(0·300·…·7000, 10회) 현행 유지 | §3-2-3 산수(`resume_window_ms` 60초와의 관계) |
| 같은 우선순위 단 안에서는 FIFO | §2-2-1 순서 계약(방 상태 통지 1단) |
| ★한 방은 한 미디어 서버가 맡고 서버 사이를 옮겨 다니지 않는다 | §4-1-6 단순 `u64` `seq` 총순서 · §9-1-1 `sfu_id` 키 |
| `T101`×`C101` = 0.5초×3 = 1.5초 | §10-4-32 `T9`=3초의 근거 |
| 방마다 무전 슬롯 audio 1 + video 1 | §4-1 100방 상한의 m-line 산수 |
| ★청취자도 명단에 보여야 한다(제품 요구) | §4-4-1 참여 단일 입구 · §4-1-3 |

### 1-3. 근거 · 기각 — 규격이 아니다

> 계약 본문(구조 · 동작 · 주제)의 규칙이 왜 그런가(R) · 무엇을 하지 않기로 했나(REJ). 소절 머리는 그 근거가 붙은 계약 자리다. 계약 판에는 싣지 않는다.

#### 1-3-1. §1-2-1 범위·용어

<a id="R-DOC-WHY-SPLIT"></a>**R-DOC-WHY-SPLIT** · 근거

★**왜 갈랐나** — 확장까지 한 문서에 넣으면 ★**무엇을 구현해야 붙는지**가 흐려진다.
문자(`0x0501`)가 안에 있고 주석이 밖인 것은 그 기준이다 — 문자는 무전 제품의 기본 표면이고,
주석은 화면 위에 그리는 기능이라 ★**없어도 통신이 성립한다.**

<a id="R-DOC-VAD-OUT"></a>**R-DOC-VAD-OUT** · 근거

★★**발성 감지(`svc=0x02`)가 밖인 이유는 다르다 — 축이 다르기 때문이다.**

★**"화자" 는 결과이고, 거기 도달하는 경로가 둘인데 서로 배타다.**

| | 회의 | ★**무전** |
|---|---|---|
| 화자를 어떻게 아나 | ★**음의 에너지를 관측한다**(발성 감지) | ★**발언권 관리의 산물로 드러난다**(§10) |
| 왜 그 방법인가 | 권한이 없으니 ★**관측 말고 알 방법이 없다** | 서버가 권한을 쥐고 있으니 ★**관측할 이유가 없다** |
| 몇 명 | 여럿(상위 N) | ★**한 명** |
| 언제 | 주기 관측 | ★**사건** |

★★**무전 방에서 RTP 를 내보내는 사람은 발언권을 쥔 한 명뿐이다.** 그러니 그 방의 발성 감지
결과는 ★**정의상 발언권 화자와 같고, 새 사실이 하나도 없다.**

★**이 문서는 무전의 계약이라 발언권 경로만 정한다.** 발성 감지는 ★**회의 제품의 표면**이고
따로 규격을 본다 — 섞을 자리를 여기 만들지 않기 위해 **밖에 둔다**(§10-4-34).
